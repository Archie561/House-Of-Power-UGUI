Transaction Service відповідає за логіку витрат ресурсів гравця. Він містить методи для обрахунку нового значення ресурсів після виконання транзакції, а також методи для визначення того, чи може гравець дозволити собі провести транзакцію. Цей сервіс єдиний який записує змінені значення ресурсів у PlayerDataService.
Оскільки різні типи ресурсів можуть мати різну логіку обробки (наприклад, у механіці законів - значення ресурсу політики не може опуститися нижче порогу рівня, а у механіці трейдів - кількість ресурсу не може перевищувати місткість відповідного складу), менеджери механік стають обробниками своїх типів ресурсів, для цього вони реалізовують інтерфейс IResourceLogicHandler і реєструють себе через метод RegisterHandler. Якщо для якогось типу ресурсу обробника немає - використовується звичайна логіка що описана власне у TransactionService.

The Transaction Service is responsible for the logic governing a player’s resource expenditure. It contains methods for calculating new resource values after a transaction is executed, as well as methods for determining whether a player can afford to carry out a transaction. This service is the only one that writes the updated resource values to the PlayerDataService.
Since different resource types may have different processing logic (for example, in the laws mechanic, a policy resource’s value cannot fall below a certain threshold, while in the trading mechanic, the quantity of a resource cannot exceed the capacity of the corresponding warehouse), mechanic managers act as handlers for their respective resource types; to do this, they implement the IResourceLogicHandler interface and register themselves via the RegisterHandler method. If there is no handler for a particular resource type, the default logic described in TransactionService is used.
